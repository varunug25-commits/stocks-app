# MarketBrief Image and Media Policy

The Phase 2 Milestone 1 auth/onboarding shell uses original vector shapes, icons, text, and company-letter fallbacks only. It adds no scraped or remotely fetched imagery. The master-spec UI kit stored under `docs/design/` was supplied by the user as an implementation reference.

## Allowed sources

Production media may come only from:

- official company press or investor-relations media with permitted usage;
- licensed editorial or stock-media providers;
- APIs whose terms explicitly allow display in this product;
- user-provided media with appropriate rights; or
- original artwork commissioned for or generated by MarketBrief.

Do not scrape publisher pages, copy arbitrary search-result images, hotlink unverified assets, or remove watermarks or attribution.

## Design-phase policy

The design shell must remain independent of external services. During this phase:

- use original local abstract artwork for editorial cards;
- use local typographic company-logo fallbacks;
- keep media metadata in local mock-data files; and
- document intended source and license fields in the data shape.

Do not imply that placeholder art is publisher photography.

## Company logos

Company logos appear in search, watchlists, stock pages, and alerts. Until a permitted logo provider is selected, use a branded local fallback made from the ticker initial and a distinct background color.

Future logo records must include:

- source URL or asset identifier;
- provider;
- retrieval date;
- permitted use or license reference; and
- fallback color and initials.

## Editorial imagery

Lead stories should use high-quality imagery with a clear relationship to the story. Each production image record must include source, author/owner when required, license or usage basis, alt text, crop focal point, and attribution text when required.

## Accessibility and performance

- Every meaningful image has useful alt text.
- Decorative artwork is hidden from accessibility services.
- Preserve focal points when cropping.
- Serve appropriately sized assets and avoid unnecessary full-resolution downloads.
- Provide a stable color or skeleton placeholder while media loads.
